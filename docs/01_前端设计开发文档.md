# 小小成长家｜前端设计与开发文档 V1.0

> 产品：小学生作业管理与成长激励工具；目标端：移动 H5 / PWA；版本：MVP 1.0；日期：2026-11-20。

## 1. 产品目标与范围
家长粘贴钉钉老师的作业通知，经 AI 解析并人工确认后发布；孩子自主查看、完成任务；家长评价表现，发放成长积分；孩子用积分申请兑换心愿。首版不直接对接钉钉、不自动判卷、不进行 AI 书写评分。

### 用户角色
- 孩子：查看/完成自己的作业、查看积分与成长记录、申请兑换心愿。
- 家长：录入/编辑/发布作业、评价、管理奖励规则和心愿、审核兑换、管理孩子账户。
- 一名家长可管理多个孩子；MVP 至少支持单家庭单孩子，数据结构预留多孩子。

## 2. 技术选型
- Vue 3 + TypeScript + Vite；Vue Router；Pinia；Tailwind CSS；Headless UI/自建基础组件；Lucide 图标。
- TanStack Query Vue 用于远程缓存、失效和重试；Axios 或 fetch 封装统一 API 客户端。
- vee-validate + zod 做表单校验；dayjs 做日期；Vitest + Vue Test Utils 单测；Playwright E2E。
- PWA：manifest、安装引导、静态资源离线缓存；网络写操作不可离线伪成功，断网时明确提示。
- UI 使用 CSS 变量主题；插画和图标优先本地静态资源，避免未授权素材。

## 4. UI 设计系统
### 视觉基调
儿童友好、轻量、清晰、温暖；参考已确认的八屏概念稿，采用柔和奶油白背景、浅紫主色、薄荷绿成功色、淡黄积分色。避免大面积高饱和、密集装饰和过多动画。

### 设计令牌（初始建议，需在实机上验收）
```css
:root {
  --bg: #F8F7FF; --surface: #FFFFFF; --primary: #7857D9;
  --primary-soft: #EFE9FF; --success: #6FCB77;
  --success-soft: #EAF8E9; --accent: #F3B944;
  --text: #242536; --muted: #74768B; --border: #E7E6F0;
  --radius-card: 20px; --radius-button: 14px;
  --shadow-card: 0 4px 18px rgba(45,35,85,.06);
}
```
- 内容宽度：移动端 320–480px 适配，平板最大 720px，桌面预览最大 960px。
- 触控区域至少 44×44px；正文建议 15–16px；重要按钮 48px 高；对比度遵循 WCAG AA。
- 导航：孩子端固定四 Tab（作业/成长/心愿/足迹）；家长端独立管理布局。
- 页面状态必须覆盖：加载中、空列表、接口失败、无网络、提交中、提交成功、权限不足。

## 5. 八个核心页面的交互规格
### 5.1 孩子端｜今日作业
- 顶部显示日期、欢迎语、头像；进度卡显示已完成/总数。
- 任务卡包含学科、类型、标题、要求摘要、完成状态；点击进入详情，完成按钮可直接切换。
- 支持日期切换；默认今天；任务按未完成优先、学科及老师指定顺序展示。
- 完成后乐观更新仅限 UI 暂态；API 失败必须回滚并提示。
- 完成状态与“已提交”状态独立；允许撤销误勾。
- 次日准备物品独立区域，不混入今日书写作业进度。

### 5.2 孩子端｜我的成长
- 当前积分、今日积分、最近流水；家长鼓励语。
- 不展示全班排名、负向惩罚榜或公开比较。
- 点击积分来源可查看对应任务或评价。

### 5.3 孩子端｜心愿小屋
- 当前目标心愿、积分进度；心愿卡：图、名称、积分、是否可兑换。
- 兑换按钮进入确认弹窗：当前余额、扣分规则、兑现说明。
- 提交后显示“等待家长审核”；未审批不得立即扣分（或后端采用预占机制时必须明确显示）。本方案采用审批通过后扣分。
- 已提交申请不可重复点击；显示兑换订单状态。

### 5.4 孩子端｜学习足迹
- 周视图：完成任务数、学习天数、积分获取、家长鼓励记录。
- 只展示有证据的数据；无数据不生成虚构评价。
- 支持按周切换和查看历史作业。

### 5.5 家长端｜AI 录入作业
- 粘贴原始通知，可选择目标孩子、作业日期；提交后展示解析中状态。
- 解析草稿逐条展示：学科、类型、标题、详细要求、页码/次数、截止时间、附件链接、是否需要提交。
- 字段可编辑、任务可删除/新增/合并；低置信度和缺失信息醒目标注。
- 检测重复通知及疑似重复任务；提供“跳过/覆盖草稿/保留”确认。
- 仅家长点击“确认发布”后才进入孩子作业清单。
- 保留原文，支持对照查看；敏感信息不应直接展示给孩子。

### 5.6 家长端｜今日成长评价
- 选择孩子与日期；展示当天作业进度。
- 评价维度：书写工整、正确率高、独立完成、主动订正、明显进步。
- 每项可配置分值；备注鼓励语；确认前展示本次总分和当日剩余上限。
- 重复评价要提示，不能通过重复点击多次发积分。

### 5.7 家长端｜奖励与心愿管理
- Tab：心愿清单、积分规则、兑换审核。
- 心愿增删改、图片上传、积分价格、库存/可用状态、兑现条件。
- 积分规则调整不追溯修改历史流水。
- 兑换审核：通过/拒绝/标记兑现/取消；拒绝原因可选填。

### 5.8 家长端｜积分记录
- 当前余额、累计获得、累计兑换；按日期/来源/类型筛选流水。
- 流水明细含关联任务、操作人、时间、备注；错误发分通过冲正流水处理，不直接编辑历史记录。

## 6. 核心组件与目录建议
```text
src/
  app/                 # router, providers, bootstrap
  assets/              # illustration, icons
  components/ui/       # Button, Card, Dialog, Badge, Progress, Toast
  components/task/     # TaskCard, TaskDetail, SubjectTag
  components/reward/   # PointsBalance, WishCard, RedemptionDialog
  features/auth/
  features/child-tasks/
  features/ai-import/
  features/growth/
  features/wishes/
  features/history/
  features/parent-admin/
  stores/               # auth, activeChild, ui
  services/             # http client, generated API types
  composables/
  styles/
  tests/
```
- 页面组件负责布局，业务逻辑放 feature composables；服务层统一处理请求、错误、认证与幂等键。
- DTO 类型优先从 OpenAPI 自动生成，禁止前后端各自维护不一致的字段枚举。

## 7. 核心状态模型
```ts
type TaskStatus = 'todo' | 'in_progress' | 'done';
type TaskType = 'writing' | 'dictation' | 'recitation' | 'reading' |
  'listening' | 'video' | 'correction' | 'preparation' | 'other';
type RedemptionStatus = 'pending' | 'approved' | 'rejected' |
  'fulfilled' | 'cancelled';
interface Task {
  id: string; childId: string; subject: string; type: TaskType;
  title: string; description?: string; assignedDate: string;
  dueAt?: string | null; status: TaskStatus;
  requiresSubmission: boolean; submittedAt?: string | null;
  completedAt?: string | null; version: number;
}
```
- 日期 API 使用 ISO 8601，时间带时区；纯作业日期使用 YYYY-MM-DD，按家庭时区计算“今天”。
- 任务更新携带 version 防止多设备覆盖；409 时刷新并提示冲突。

## 8. API 对接约定
统一前缀 `/api/v1`；JSON；错误格式 `{code,message,details,request_id}`；列表分页 `{items,next_cursor}`。认证采用 HttpOnly Secure SameSite Cookie + CSRF 保护，跨域按白名单配置。关键写操作传 `Idempotency-Key`。

主要调用：
- `POST /imports/parse` → AI 解析草稿；`GET /imports/{id}`；`POST /imports/{id}/publish`
- `GET /children/{id}/tasks?date=...`；`PATCH /tasks/{id}/status`
- `GET /children/{id}/points`；`GET /children/{id}/point-transactions`
- `POST /children/{id}/growth-reviews`
- `GET /children/{id}/wishes`；`POST /children/{id}/redemptions`
- `PATCH /redemptions/{id}/decision`；`PATCH /redemptions/{id}/fulfillment`

## 9. 前端安全与体验
- 路由守卫只用于体验，真正权限由后端验证；家长入口必须重新验证或有独立家长会话。
- 不在 localStorage 保存 access token、孩子敏感信息或 AI 服务密钥。
- 老师通知作为不可信文本显示，防 XSS；富文本默认禁用或严格清洗。
- AI 输出只能作为草稿；不把模型返回的 HTML 直接插入 DOM。
- PWA 缓存不包含私人 API 响应；退出登录清理私有查询缓存。

## 10. 前端验收标准
1. 家长粘贴一段包含 3 学科、5 项作业的通知，能够编辑并发布。
2. 孩子在手机上完成、撤销任务，跨设备刷新后状态一致。
3. 任务完成率正确，已提交不等同于已完成。
4. 家长评价后积分变化与流水一致；重复点击不重复加分。
5. 兑换申请后显示待审核，家长批准后才扣分。
6. 320px 手机宽度无横向溢出；键盘弹出时操作按钮可达。
7. 网络失败有明确提示；重试不会造成重复写入。
8. Playwright 覆盖导入→发布→完成→评价→兑换→审核的主流程。

## 11. 前端实施顺序
P0：项目骨架、主题组件、登录与权限、任务列表与详情。
P1：AI 导入确认、成长评价、积分与心愿、兑换审核。
P2：历史足迹、PWA、无障碍优化、自动化测试与性能优化。
