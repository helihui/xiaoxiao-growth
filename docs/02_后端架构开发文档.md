# 小小成长家｜后端架构与开发文档 V1.0

> 面向 FastAPI 开发与 Codex 实施；日期：2026-11-20。后端以可靠的作业管理、AI 草稿解析、可审计积分账本和兑换事务为核心。

## 1. 技术架构
- Python 3.12+；FastAPI；Pydantic v2；SQLAlchemy 2.x；Alembic；PostgreSQL 16+（生产）；SQLite（仅单机开发）。
- Redis 可选：限流、短时任务状态；MVP 不强依赖。AI 解析可同步短请求或后台任务，耗时较长时采用持久化 Job + worker。
- 对象存储：兼容 S3/MinIO，上传照片与心愿图片；MVP 可先不实现附件上传。
- OpenAI-compatible 模型接口经服务端调用；超时、重试、结构化校验、审计和成本限制。
- 统一 UTC 存储时间戳，家庭配置 IANA 时区（默认 Asia/Shanghai）。

### 分层
`API Router → Auth/Permission → Application Service → Domain Rules → Repository/DB`；AI Adapter 独立于业务服务；积分/兑换使用数据库事务，不允许模型直接写账本。

## 2. 领域实体与数据库设计
所有表建议 UUID 主键，`created_at`/`updated_at`，必要处 `deleted_at`；金额无关，仅存整数积分。

| 表 | 关键字段 | 约束与用途 |
|---|---|---|
| users | id, login_identifier, password_hash, status | 家长/孩子账户，不存明文密码 |
| families | id, name, timezone | 家庭租户边界 |
| family_members | family_id, user_id, role | role=parent/child；复合唯一 |
| children | id, family_id, user_id?, nickname, avatar_key | 可先无独立登录 |
| subjects | id, family_id, name, sort_order | 学科配置 |
| import_batches | id, family_id, child_id, source_text, source_hash, status, ai_model, error_code | 原文及 AI 解析批次 |
| import_tasks | id, batch_id, payload_json, confidence, warnings_json, edited | 待家长确认的草稿 |
| tasks | id, family_id, child_id, subject_id?, type, title, description, assigned_date, due_at, status, completed_at, requires_submission, submitted_at, source_batch_id, version | 正式作业 |
| task_attachments | id, task_id, kind, url_or_key | 视频链接/文件引用 |
| reward_rules | id, family_id, code, title, points, daily_limit, enabled | 家长可配置的奖励规则 |
| growth_reviews | id, family_id, child_id, task_id?, review_date, rule_id, points_awarded, note, reviewer_id, dedupe_key | 评价与授分关联 |
| point_accounts | child_id, balance, earned_total, spent_total, version | 快速余额快照 |

| wish_items | id, family_id, child_id?, title, description, image_key, cost_points, active, fulfillment_terms | 心愿目录 |
| wish_goals | id, child_id, wish_item_id, is_primary | 当前长期心愿 |
| redemption_orders | id, child_id, wish_item_id, cost_snapshot, status, requested_at, decided_at, fulfilled_at, decided_by, reason, version | 兑换订单 |
| audit_logs | id, family_id, actor_id, action, target_type, target_id, metadata_json, created_at | 重要操作审计 |
| idempotency_records | actor_id, key, endpoint, request_hash, response_json, expires_at | 幂等写入响应缓存 |

### 必须建立的约束
- `point_accounts.balance >= 0`；积分值为整数。
- `point_transactions` 按业务来源建立唯一索引，例如 `(child_id, source_type, source_id, type)`；冲正交易允许独立类型与引用。
- `growth_reviews.dedupe_key` 在家庭/孩子范围内唯一；同一天同规则是否可多次评价由规则决定。
- `import_batches` 的 source_hash 用于提示重复，不应仅凭 hash 自动覆盖历史作业。
- `redemption_orders` 状态迁移受控；`cost_snapshot` 固定历史兑换价格。
- `tasks.version` 乐观锁；所有子对象查询强制 family_id 与 child_id 所属关系校验。

## 3. 认证与授权
- 家长：密码或可信身份登录，密码 Argon2id；服务端 Session + HttpOnly/Secure/SameSite Cookie；CSRF Token；会话轮换与注销。
- 孩子：MVP 推荐家长授权的设备会话或孩子 PIN（仅辅助，须限流和防暴力尝试）；孩子只可访问本人资源。
- 角色：parent 可管理本家庭；child 只能更新本人任务状态、提交本人兑换申请和读取本人积分/心愿。
- 每个 API 必须验证对象的 `family_id`，防止仅凭 ID 越权（IDOR）；操作审计记录 actor。
- 多家庭用户需显式选择 active family，禁止从客户端传来的 family_id 直接信任。

## 4. API 设计
统一 `/api/v1`；成功返回资源或 `{items,next_cursor}`；错误统一 `{code,message,details,request_id}`。所有修改接口验证角色、数据归属和版本。

### 4.1 作业导入与管理
- `POST /imports/parse` 家长提交 `{child_id, assigned_date, source_text}`；返回 `{batch_id,status}`；限制文本长度。
- `GET /imports/{batch_id}` 查询解析草稿及警告；仅家长。
- `PATCH /imports/{batch_id}/tasks/{draft_id}` 修改解析草稿。
- `POST /imports/{batch_id}/publish` 幂等发布；请求含草稿版本；数据库事务创建任务并标记 published。
- `GET /children/{child_id}/tasks?date=YYYY-MM-DD` 获取当天任务。
- `POST /children/{child_id}/tasks` 家长手动新增。
- `PATCH /tasks/{task_id}` 家长编辑任务。
- `PATCH /tasks/{task_id}/status` 孩子/家长更新状态 `{status,version}`。
- `PATCH /tasks/{task_id}/submission` 更新独立提交状态，按权限限制。

### 4.2 积分与成长评价
- `GET /children/{id}/points` 返回余额、累计获得、累计兑换。
- `GET /children/{id}/point-transactions?cursor=...` 返回流水。
- `GET /reward-rules`、`PUT /reward-rules/{id}` 家长管理。
- `POST /children/{id}/growth-reviews` 家长评价并发分；传 `{rule_id,review_date,task_id?,note,dedupe_key}` 与 Idempotency-Key。
- `POST /growth-reviews/{id}/reverse` 家长纠错，生成冲正流水，不删除原流水。

### 4.3 心愿与兑换
- `GET /children/{id}/wishes` 孩子可读。
- `POST /wishes`、`PATCH /wishes/{id}` 家长维护。
- `POST /children/{id}/redemptions` 孩子申请，初始 pending，不扣分。
- `GET /redemptions?status=pending` 家长查看。
- `PATCH /redemptions/{id}/decision` 家长批准或拒绝。
- `PATCH /redemptions/{id}/fulfillment` 家长标记已兑现。
- `POST /redemptions/{id}/cancel` 按状态规则取消与必要时退款。

## 5. AI 作业解析设计
### 输入
老师原始通知、家长选择的作业日期、家庭时区、可选已存在任务摘要；不得发送与解析无关的孩子身份信息。

### 解析输出 JSON Schema（示例）
```json
{
  "tasks": [{
    "subject": "语文",
    "type": "writing",
    "title": "抄写第12课生字",
    "description": "每字3遍",
    "assigned_date": "2026-11-20",
    "due_at": null,
    "requires_submission": false,
    "attachment_urls": [],
    "confidence": 0.94,
    "warnings": []
  }],
  "batch_warnings": []
}
```
### 解析原则
1. AI 只负责抽取与归类，不得虚构老师未给出的页码、视频链接、截止时间、评分或任务。
2. “群里的视频”等缺失链接标记 `missing_attachment`。
3. 一条通知可能拆出多项任务；准备物品单独分类。
4. 不确定字段置空并附 warnings；模型 JSON 经 Pydantic 严格校验。
5. 将原文视为不可信数据，抵御提示词注入；禁止工具调用或外部执行。
6. 解析草稿必须经家长确认才能发布；模型失败允许手工创建任务。
7. 设定超时、最大 token、费用限额；记录模型版本、耗时、失败类型，不在日志中打印完整通知。

### 重复检测
- `source_hash = SHA256(normalize(source_text)+child_id+assigned_date)`；命中时提示疑似重复。
- 任务级使用学科+标准化标题+日期+要求进行相似检测，仅提示家长，不自动删除不同老师的合法任务。
- 发布接口使用唯一批次状态与事务避免重复发布。

## 6. 积分账本设计（强事务）
积分是整数记账单位，不能只靠前端累计。

### 发分事务
1. 验证家长权限、规则是否启用、单日上限、去重键。
2. `SELECT ... FOR UPDATE` 锁定孩子的 point_accounts（SQLite 开发时用串行写入策略）。
3. 插入 growth_review 与正向 point_transaction；更新 balance/earned_total。
4. 写审计日志，事务提交后返回新余额。
5. 相同 Idempotency-Key 与相同请求体重复调用返回原结果；同 key 不同请求体返回 409。

### 自动奖励
“完成全部作业”需定义结算时点：按家庭本地日期及当日已发布任务集合计算。建议在当天首次满足条件时授分，若之后追加任务不重复发放；必要时由家长调整。使用业务唯一键 `daily_completion:{child}:{date}` 防重。

### 撤销奖励
不修改或删除历史交易；创建 `reversal` 交易并关联原交易。若撤销导致余额不足，禁止负余额，改为待处理纠错，由家长确认补偿方案；不得暗中扣成负数。

## 7. 兑换状态机与并发
`pending → approved → fulfilled`；`pending → rejected`；`pending/approved → cancelled`。`fulfilled` 不可普通取消，需要家长发起单独纠错流程。

### 审批通过事务
1. 校验家长权限、订单仍为 pending。
2. 锁定订单与孩子积分账户，检查余额 >= cost_snapshot。
3. 写负向 point_transaction（source_id=redemption_id 唯一）、更新 balance/spent_total。
4. 订单改 approved，记录审批人、时间；事务提交。
5. 并发两次审批只允许一笔扣分；余额不足返回业务错误 `INSUFFICIENT_POINTS`，订单仍 pending。

### 已批准订单取消
锁定订单与账户，写唯一退款交易、恢复余额与累计兑换口径（建议 spent_total 采用净支出），订单改 cancelled；幂等重复取消不重复退款。

## 9. 安全、隐私与运维
- 适用儿童数据最小化：默认昵称而非实名；不上传无关聊天内容；支持家长删除数据和导出。
- 全站 HTTPS；服务端密钥通过环境变量/Secret 管理；数据库与对象存储按最小权限授权。
- 上传限制类型、大小、病毒扫描或安全校验；文件 URL 使用短期签名，避免公开暴露。
- AI 请求脱敏并限制供应商留存；明确隐私说明、监护人同意和数据保留策略，按部署地区法律评估合规。
- 限流：登录、PIN、AI 解析、兑换提交；防 CSRF/XSS/SQL 注入/越权。
- 生产数据库每日备份，定期恢复演练；Alembic 迁移先备份；结构化日志和 request_id。
- 健康检查 `/health/live`、`/health/ready`；记录 AI 成功率、导入失败率、API P95、积分对账异常。
- 定期对账：`point_accounts.balance == SUM(point_transactions.amount)`；异常报警，不静默修复。

## 10. 部署方案
- 开发：Docker Compose 启动 backend + PostgreSQL；前端 Vite 独立热更新；SQLite 仅单机测试。
- 生产：Nginx HTTPS 反代 `/api` 至 Uvicorn/Gunicorn worker，静态前端由 Nginx 托管；PostgreSQL 持久化卷；对象存储可选。
- `.env.example`：DATABASE_URL、SESSION_SECRET、AI_BASE_URL、AI_API_KEY、AI_MODEL、CORS_ORIGINS、APP_TIMEZONE、STORAGE_*；禁止提交真实密钥。
- CI：ruff、mypy/pyright、pytest、Alembic migration check、依赖安全扫描、Docker 构建。

## 11. 测试与验收
### 必测集成场景
1. 同一通知重复解析并发布，不产生重复正式任务。
2. AI 返回错误 JSON、缺少字段、恶意提示词时不污染数据库。
3. 孩子不能访问其他孩子的数据，不能调用家长评价或审批接口。
4. 同一个评价并发提交 10 次，仅生成一笔奖励流水。
5. 两个并发兑换审批，总扣分不得超过余额。
6. 审批成功后取消，积分准确退回且只退一次。
7. 兑换申请时不扣分，拒绝时不扣分，批准时扣分。
8. 错误发分冲正有完整审计记录。
9. 家庭时区跨午夜的任务日期与奖励归属正确。
10. 数据库重启、迁移和备份恢复后账本一致。

### API 错误码建议
`UNAUTHORIZED`, `FORBIDDEN`, `NOT_FOUND`, `VALIDATION_ERROR`, `VERSION_CONFLICT`, `DUPLICATE_IMPORT`, `DUPLICATE_REWARD`, `INSUFFICIENT_POINTS`, `INVALID_REDEMPTION_STATE`, `AI_PARSE_FAILED`, `RATE_LIMITED`。

## 12. 开发里程碑
- M1：数据库迁移、家庭/孩子/权限、作业 CRUD 与状态。
- M2：AI 导入草稿、人工编辑确认、发布去重。
- M3：奖励规则、评价发分、积分流水与对账。
- M4：心愿、兑换申请、审核扣分、取消退款。
- M5：审计、安全、集成测试、备份部署、接口文档。

## 13. 开发完成定义
- OpenAPI 文档可访问并与前端类型一致。
- 主要业务 API 有单元与集成测试，账本关键事务具备并发测试。
- 无跨家庭越权；无重复积分/重复扣分；无负余额。
- 完成端到端：粘贴通知→AI 草稿→家长发布→孩子完成→家长奖励→孩子申请→家长审批→兑现。
- 具备可重复部署的 Docker Compose、迁移脚本、环境模板与 README。
